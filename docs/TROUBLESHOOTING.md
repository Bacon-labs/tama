# Troubleshooting

Start with:

```sh
tama doctor
```

`doctor` checks required tools, the project Lean/Lake/solc versions, Verity dependency resolution, generated directories, and `tama.lock` drift. Use `tama doctor --fix` only for repairs Tama says are safe.

## Not in a Tama project

If a project command reports that it cannot find a Tama project root, run it from a directory containing `tama.toml` or pass `--root`:

```sh
tama --root /path/to/project doctor
```

## Stale lock

`--locked` fails when tracked inputs changed. Run:

```sh
tama doctor
tama update
```

If you intentionally changed only generated directories or dependency metadata, `tama doctor --fix` may be enough. CI should use `--locked` after update/init has produced the intended lock state.

## Missing or wrong solc

Tama requires the `solc` version configured in `[yul].solc`.

```sh
solc --version
tama doctor
```

Install the configured version or set `TAMA_SOLC` to a matching binary. A mismatched binary fails before bytecode extraction.

## Lake dependencies or offline builds

`tama check` and `tama build` do not run `lake update`. If Lake dependencies are missing, run:

```sh
lake update
```

For repeated or offline work, keep a clean checkout cache in `TAMA_LAKE_PACKAGE_CACHE`. Tama seeds `.lake/packages` only when the cached Git HEAD exactly matches `lake-manifest.json`. With `--offline`, Tama then refuses to invoke Lake if any pinned git package is still missing, dirty, or at another revision under `.lake/packages`.

## Forge dependencies

`tama init` installs pinned `forge-std` with Foundry as a Git submodule. Tama may use `--shallow` and `--no-commit` when supported, but it does not use `--no-git`.

For Solidity-side dependency changes, use Forge directly:

```sh
forge install owner/repo
forge update
```

## Generated files were edited

Tama overwrites generated files only when the first line is:

```text
// GENERATED by tama; do not edit.
```

If a generated bridge file was hand-edited, move the changes into Verity source/spec/proof or a user-owned Solidity file, then rerun `tama build`.

## Missing bytecode or inspect artifacts

If `tama inspect` reports a missing artifact, rebuild the project:

```sh
tama build
```

For trust output, run `tama build` and then:

```sh
tama audit trust-boundary
```

## Coverage failures

Mirror coverage must point to a Foundry test file under Foundry's test directory and to a contract-qualified property symbol:

```text
test/verity/ERC20Lite.t.sol:ERC20LiteTest.testFuzzTransferPreservesTotalSupply
```

The function part must be a fuzz test named `testFuzz*` or an invariant named `invariant_*`. Example tests can exist as smoke tests, but they do not satisfy obligation coverage.

## Trust-boundary failures

`sorryAx` is always denied. Remove `sorry` from public obligations before release.

Other axioms must be intentionally allowlisted in `tama.toml` with a non-empty reason:

```toml
[trust.allow_axioms]
"Classical.choice" = "Lean standard classical reasoning accepted for this project"
```

Do not allowlist compiler assumptions or axioms until you understand the generated `artifacts/trust-report.json`, `artifacts/assumption-report.json`, and `artifacts/trust-probe/axioms.json`.

## Invalid config

`tama.toml` is strict. Unknown Tama-owned keys and malformed TOML fail instead of being ignored. Keep Foundry settings in `foundry.toml`, and rerun:

```sh
tama doctor
```
