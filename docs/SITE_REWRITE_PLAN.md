# Site rewrite plan

## Purpose

Rewrite the Tama website and public documentation from scratch around the
"jade and soul" identity (玉 = jade, 魂 = soul) the name carries in Japanese.
The current site is a generic SaaS template, the copy assumes deep Verity
knowledge, and the docs are an unstructured dump of internal reference files.
The rewrite builds a custom Astro site with a Japanese-influenced jade design
language, structures docs as a real learning curve (intro → tutorial →
concepts → guides → reference), and ships through a GitHub Actions Pages
workflow so the build can support a real framework instead of a single-file
HTML page.

## Steps

1. **Scaffold an Astro 5 project at `site/`.** Use the minimal "empty"
   template (no Starlight — Starlight has its own visual identity). Add
   `@astrojs/mdx`, `@astrojs/sitemap`, and `astro-icon`. Pin Node ≥ 20 in
   `site/package.json` `engines`. Set `astro.config.mjs` `site:
   "https://tama.tools"`, `trailingSlash: "ignore"`, `build.format: "file"`,
   `markdown.shikiConfig` with `themes: { light: "github-light", dark:
   "github-dark" }`, and inline-stylesheets `"auto"`.

2. **Define the design system in `site/src/styles/tokens.css`.**
   Colors: `--jade-900 #0c3a31`, `--jade-700 #1f5f4f`, `--jade-500 #3d8073`,
   `--jade-300 #8db8ab`, `--jade-100 #dde9e3`, `--jade-mist #eef4f0`,
   `--washi #f5efe2`, `--washi-soft #fbf7ed`, `--sumi #11150f` (body ink),
   `--sumi-soft #2a3530`, `--shu #b9442e` (vermillion seal accent),
   `--brass #a78947` (verified/proof accent). Type scale: display
   `"EB Garamond", "Noto Serif JP", serif`, body `"Inter", system-ui,
   sans-serif`, mono `"JetBrains Mono", ui-monospace, monospace`. Self-host
   Inter, EB Garamond, JetBrains Mono via `@fontsource` packages so there is
   no Google CDN dependency. Define spacing scale (4-8-12-16-24-32-48-72-104),
   radius (`--r-sm 4px`, `--r 8px`, `--r-lg 14px`), and shadow tokens.

3. **Add the washi paper background and kintsugi separator as SVG primitives**
   under `site/src/components/ornaments/`. `WashiTexture.astro` is a tiled SVG
   noise overlay at ~3% opacity. `Kintsugi.astro` is a horizontal gold-veined
   SVG seam used between sections. `HankoSeal.astro` renders a small
   vermillion square with white kanji 玉 used as a brand mark and end-of-page
   stamp.

4. **Build the layout primitives in `site/src/layouts/`.**
   `BaseLayout.astro` ships the head, washi background, sticky header
   (wordmark + nav), footer (hanko seal + repo link + license), and a single
   `<slot />`. `MarkLayout.astro` extends BaseLayout for prose pages with
   max-width 720px and serif headings. `DocLayout.astro` extends BaseLayout
   for reference docs with a left sidebar (section nav rendered from
   `src/content/config.ts` ordering) and a right rail TOC autogenerated from
   the page's `<h2>`/`<h3>`.

5. **Build the components in `site/src/components/`.**
   `Wordmark.astro` (serif "Tama" + small kanji 玉魂 underneath at lower
   weight). `PrimaryNav.astro` (Start / Concepts / Guides / Reference /
   GitHub). `RuneTerminal.astro` (a styled code block with stone-engraved
   inner shadow, jade glow on hover, and a subtle vertical light sweep
   animation that runs once on intersection). `Callout.astro` with `kind` =
   `note | proof | warning | seal`. `PipelineDiagram.astro` — an SVG
   horizontal flow `Verity source → proof → Yul → bytecode → bridge → Foundry`
   with audit checks branching off as small jade dots.

6. **Wire content collections.** `site/src/content/config.ts` defines two
   collections: `pages` (intro, install, start, concepts, troubleshooting,
   limitations, privacy) and `reference` (cli, manifest, artifacts, config,
   audit). Both use Markdown/MDX with frontmatter `{title, summary, order,
   section?}`.

7. **Write the home page `site/src/pages/index.astro`** with:
   hero = serif wordmark + Japanese kanji 玉魂 + one-sentence "what is Verity"
   + one-sentence "what Tama does" + two CTAs (Get started / Read the docs).
   A second band: animated `RuneTerminal` cycling through `tama init`,
   `tama build`, `tama audit`. Three composed sections answering "Why a
   verified contract?" / "What Tama gives you" / "How the pipeline fits."
   Footer with hanko seal.

8. **Write `site/src/pages/install.astro`** with a single `curl | sh` block,
   the manifest verification story (TLS + signed SHA-256 manifest), and
   `tamaup` post-install commands.

9. **Write the tutorial `site/src/pages/start.mdx`** as a 20-minute path:
   what we'll build (a TipJar that proves "deposits never decrease the
   recorded total"), `tama init`, walking through every file the scaffold
   created, editing one spec/proof, running `tama build`, reading the audit
   output, modifying the contract, watching audit fail, fixing it. The
   reader should finish able to write and prove a property.

10. **Write `site/src/pages/concepts.mdx`** with: "What is Verity?" (one
    paragraph, no jargon); the three layers (implementation, spec, proof);
    obligation, mirror test, manifest, bridge, trust boundary,
    allowlisted axiom — each defined plainly with a short example.

11. **Write the guides under `site/src/pages/guides/`:**
    `audits.mdx` (how to read `tama audit` output, each check explained
    with a real failure example), `foundry.mdx` (how Tama and Foundry share
    the project, when to call `forge` directly), `proofs.mdx` (writing a
    new obligation, marking it for mirror coverage, dealing with `sorry`).

12. **Write the reference under `site/src/pages/reference/`:**
    `cli.mdx` (every `tama` and `tamaup` command, one section each with
    flags and a small example — anchored deep links per command),
    `config.mdx` (full `tama.toml` and `tama.lock` reference),
    `manifest.mdx` (manifest schema with annotated example),
    `artifacts.mdx` (every generated path and what reads/writes it).

13. **Move static assets into `site/public/`:** copy `installer/install.sh`
    to `site/public/install.sh`, write `site/public/CNAME` containing
    `tama.tools`, write `site/public/robots.txt` allowing all and
    referencing `/sitemap-index.xml`, and add a small `site/public/favicon.svg`
    (jade circle with kanji 玉).

14. **Add the deploy workflow `.github/workflows/deploy-docs.yml`.** Trigger
    on push to `main` when `site/**` or `installer/install.sh` changes, plus
    `workflow_dispatch`. Job `build`: Node 20, `npm ci` in `site/`, copy
    `installer/install.sh` to `site/public/install.sh` (so the published
    install URL keeps working), run `npm run build`, upload
    `site/dist` via `actions/upload-pages-artifact@v3`. Job `deploy`: needs
    `pages: write` and `id-token: write`, uses
    `actions/deploy-pages@v4`. Concurrency group `pages` with
    `cancel-in-progress: false`.

15. **Delete the old single-file site:** remove `docs/index.html`,
    `docs/styles.css`, `docs/install.sh`, `docs/CNAME`. Keep
    `docs/reference/SPEC.md`, `docs/reference/IMPLEMENTATION_PLAN.md`,
    `docs/reference/RELEASE.md` as repo-only contributor docs (they are
    not surfaced on the public site nav). Delete the now-redundant
    `docs/reference/QUICKSTART.md`, `COMMANDS.md`, `AUDIT.md`,
    `GENERATED_ARTIFACTS.md`, `TROUBLESHOOTING.md`, `VERITY_COMPAT.md`,
    `LIMITATIONS.md`, `PRIVACY.md` because their content has moved to
    the site collection.

16. **Rewrite `README.md`** with: one-sentence project description, install
    command, link to https://tama.tools, the four most-common commands,
    and a single "Development" block. Drop the doc-page list — the website
    is the doc surface. Keep the link to `docs/reference/SPEC.md` for
    contributors.

17. **Add `site/.gitignore`** for `node_modules`, `dist`, `.astro`, plus a
    repo-root `.gitignore` entry if one is missing for `site/node_modules`
    and `site/dist`.

18. **Build locally:** `cd site && npm install && npm run build`. Verify
    `site/dist/index.html`, `site/dist/install.sh`, `site/dist/CNAME`,
    `site/dist/sitemap-index.xml`, and `site/dist/start/index.html` exist
    and that the home page renders the wordmark, hero, and pipeline diagram.

## End state

- `site/` contains an Astro 5 project that builds the public website.
- `site/src/styles/tokens.css` defines the jade/washi/sumi/vermillion
  design tokens and is imported by `BaseLayout.astro`.
- The site nav surfaces only public pages: Start, Concepts, Guides,
  Reference, GitHub.
- `https://tama.tools/` shows the new home page with the serif wordmark,
  kanji 玉魂, one-sentence Verity explanation, and a working install CTA.
- `https://tama.tools/start` is a complete first-contract tutorial that a
  reader with no Verity background can follow to a green build and a
  passing audit.
- `https://tama.tools/concepts` defines every Tama and Verity term used
  elsewhere in the docs.
- `https://tama.tools/reference/cli` documents every `tama` and `tamaup`
  command with deep-linkable anchors.
- `https://tama.tools/install.sh` returns the same script bytes as
  `installer/install.sh`.
- `.github/workflows/deploy-docs.yml` builds `site/` and publishes
  `site/dist` to GitHub Pages on every push to `main` that touches
  `site/**` or `installer/install.sh`.
- `docs/index.html`, `docs/styles.css`, `docs/install.sh`, `docs/CNAME`,
  and the public reference Markdown files are removed from the repo.
- `docs/reference/SPEC.md`, `IMPLEMENTATION_PLAN.md`, and `RELEASE.md`
  remain in the repo as contributor docs but are not linked from the
  public site nav.
- `README.md` is short and points at `https://tama.tools`.
- `cd site && npm run build` succeeds locally with no errors.
