Why Tama

Verity work becomes one reproducible project flow.

One command surface

Tama ties together Lean/Lake, Verity codegen, solc, Foundry, lockfiles, and generated artifacts behind commands that are easy to remember.

Proofs stay in the path

Builds validate proof modules before bytecode and bridges are produced, so contract artifacts are connected to the obligations they rely on.

Foundry remains native

A Tama project is also a Foundry project. Run forge directly, write mirror tests, and keep Solidity-side workflows where they belong.

Pipeline

From Verity source to audited bytecode.

Tama keeps the moving parts visible: Lean checks, Verity outputs, manifests, solc bytecode, generated Solidity bridges, Foundry builds, and audit checks.

  1. 01Scaffold

    Create a Foundry-compatible ERC20Lite starter or add another Verity contract.

  2. 02Check

    Run the fast implementation and spec Lean check while proofs are still in progress.

  3. 03Build

    Elaborate proofs, generate Yul and manifests, compile bytecode, and build Foundry targets.

  4. 04Audit

    Review structure, selectors, storage layout, coverage, and trust-boundary evidence.
